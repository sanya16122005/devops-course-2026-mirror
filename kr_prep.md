# Подготовка к контрольной работе №1

## 1. Когда я выберу rebase, а когда merge? Почему?

**Rebase** — для своей локальной ветки, которую ещё никто не видел. Он переписывает
коммиты поверх свежей `main`, история остаётся линейной, лишний merge-коммит не появляется.
Пример: работал над фичей три дня, за это время `main` ушла вперёд — делаю `git rebase main`,
чтобы вливать уже актуальный код. Плюс `git rebase -i` убирает мусорные коммиты
(«wip», «oops», «fix typo») перед открытием Pull Request.

**Merge** — для вливания завершённой ветки в `main` и вообще для любых общих веток.
Он ничего не переписывает и фиксирует сам факт слияния отдельным коммитом с двумя родителями.
Пример: PR влит на GitHub — видно, когда фича попала в продакшен, и её легко откатить
одним `git revert` merge-коммита.

Короткое правило: **rebase — до публикации, merge — после**.

## 2. Что произойдёт, если я сделаю rebase публичной ветки, с которой работают коллеги?

Rebase создаёт **новые коммиты с новыми хешами**, а старые остаются только у коллег.
Обычный `git push` будет отклонён (non-fast-forward), и придётся делать `push --force`.
После этого у коллеги его локальная ветка и удалённая разойдутся: `git pull` попытается
слить две параллельные истории, и одни и те же изменения задвоятся, а часть работы
может потеряться при неаккуратном разрешении конфликтов.

Итог: сломанная история у всей команды и ручное восстановление через `git reflog`.
Отсюда золотое правило: **never rebase public branches**.

## 3. Зачем нужен multi-remote и в каких реальных сценариях он применяется?

Multi-remote — это несколько удалённых репозиториев у одного локального. Сценарии:

- **Зеркало (mirror) для бэкапа.** Основной репозиторий на GitHub, зеркало на GitLab
  или на внутреннем сервере. Если основная площадка недоступна, работа не встаёт.
- **Импортозамещение и санкционные риски.** Российские команды держат копию на Gitverse
  или в self-hosted GitLab.
- **Форк в OpenSource.** `origin` — свой форк, `upstream` — репозиторий проекта,
  откуда забираются свежие изменения.
- **Разные аудитории.** Публичный репозиторий для пользователей и приватный для внутренней разработки.

Настраивается через `git remote add`, а push сразу в оба — через
`git remote set-url --add --push origin <второй_адрес>`.
